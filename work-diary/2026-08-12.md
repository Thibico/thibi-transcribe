## The gap that was on the list

`S3_INTERNAL_ENDPOINT`, overview amendment 43. SigV4 signs the `Host` header, so a presigned
URL minted by a CLI on this laptop against `localhost:9000` is rejected **403** the instant
the sidecar asks for it as `minio:9000`. `S3ObjectStore` already had the seam — a
`signingClient` separate from the I/O client — but its own doc describes the mirror-image
case, signing a *public* URL so a browser can fetch audio through Caddy in Phase 10. Two
audiences, one of them unconfigured.

Small, and it was only ever interesting because of what it unblocked.

## The demo that looked like it worked

Phase 3's Verification section says, in the plan, to rename a speaker and then re-run
`thibi transcribe … --diarize`, commented `# new run`. So that is what I ran. The rename
stuck, the second run completed, `thibi speakers list` still showed **Daw Khin**, and the
sequence appeared to pass.

It proved nothing. `thibi transcribe` mints a fresh **job** for a byte-identical file — the
`media_assets` row is content-addressed and deduped, the `jobs` row is not — so the second
run's speakers were created on a different job entirely, and the job carrying the rename had
simply not been touched. The name survived because nothing had happened to it.

The tell was in the CLI's own output the whole time: it printed `new` beside both speakers,
and I read the speakers list instead. Amendment 46; Verification is corrected to
`thibi diarize run <runId>`, which re-diarizes in place.

## The defect underneath it

Running the *correct* sequence produced the real bug, and it is the one this entire feature
exists to prevent:

```
speaker-00  (unnamed)    0%   0 segments    0 words
speaker-01  Daw Khin     0%   0 segments    0 words
speaker-02  (unnamed)   34%   4 segments   39 words
speaker-03  (unnamed)   66%   5 segments   62 words
```

A human's name, orphaned in place. Worse than losing it, because the speakers list still
shows it and nothing looks broken until somebody exports a transcript.

The cause was one clause. `persist.ts` read prior attribution with `and s.run_id <> $2`,
excluding the run being diarized — correct when a *new* run matches against earlier ones,
fatal for `thibi diarize run`, which re-diarizes in place. With the current run excluded
there was no prior attribution at all, `matchSpeakers` got an empty list, and every fresh
label minted a new row.

**And `thibi transcribe` mints a new job, so it never reaches the matcher either.** Between
the two, identity matching — the Hungarian solver, the overlap floor, the tie-breaking, the
property tests, all of it — had never once run against a non-empty prior through any door a
user has.

The unit test was green the entire time. It built a **new run** for each pass, which is the
case that works. There is now a same-run test, and it asserts not just that the row was
reused but that the named speaker still *holds segments* — "the row survived" and "the name
still means something" are different claims, and only the second one is the feature.

The lesson is the reusable part: **ask what shape the real caller passes, not what shape is
convenient to construct.** That is now in the handoff note.

## `--job`, decided and built

Amendment 46 went to the user as an open question and came back yes, so `thibi transcribe`
now takes `--job <id>` and attaches the run to an existing job instead of minting one.

Verified across **two different providers**, because "same file, better model" is the
workflow it exists for rather than a re-run of the same thing: OpenAI with `--diarize`,
rename `speaker-01` to Daw Khin, then Groq into the same job — both speakers `carried
across`, Daw Khin holding 9 segments and 124 words.

**The guard is the half worth reading.** A job holding a different recording is refused
outright. A speaker name is a fact about a *recording*, so the alternative is silent and
unrecoverable: the run succeeds, the Hungarian matcher places a human's names onto a
timeline they never listened to by coincidental overlap, nothing is flagged, and the only
symptom is a transcript quoting the wrong person. Two files and one pasted job id is easy to
do and nearly impossible to notice afterwards. There is also a test that the rejected asset
row does not survive the rollback, since the guard throws after the insert — otherwise every
mistyped id would leak an orphan.

Both new errors print their message without a stack trace, joining `ProbeAbort`: these are
things the user got wrong, and the one line that helps should not arrive under twelve that
do not. That branch now names three errors, and a fourth should become a shared marker.

One thing left alone and written down instead: `thibi speakers list` counts across every run
of the job, so after two runs it reports 8 segments for a speaker with 4 per run. Consistent
with speakers being job-scoped, and it still reads oddly. A per-run view is a Phase 13
question.

## The contract test, and why it is not the one the plan asked for

Third sitting. Phase 3's last unblocked Definition-of-done item, and it was unblocked by the
presign fix above: a contract test cannot be written against a real run until a real run can
reach its audio.

The plan specified `PyannoteSource` against the container "with the canned pipeline", and
that is the part that did not survive contact. The pytest suite fakes the pipeline by
**monkeypatching in-process**, which nothing outside the process can do; making the same fake
available to a container means shipping a fake-pipeline branch in production code, to
newsrooms, so that a test can be fast. Worse, it aims the test away from the thing that
actually drifts. Amendment 42 from yesterday is the whole argument in one line: thirty green
pytest tests against a canned pyannote 3.x `Annotation`, and the real 4.x returns
`DiarizeOutput`. A canned pipeline would have been green through that too.

So it runs the model. Eleven seconds of audio costs about forty seconds of CPU inside Docker
Desktop's Linux VM — the same macOS penalty S6 recorded — and the test skips itself, naming
the missing service, unless `/health` says the model is loaded. Amendment 47.

Six assertions, and the rule for each was that it must fail for a reason the fake-source
suite cannot see: the task id agrees with what `/v1/tasks/by-key` derives from the step key;
a resubmit of the same key lands on the same task; a *different* key comes back as
`DiarizerBusyError` carrying `retryAfterMs`; an unknown id polls back retryable rather than
throwing; a real result's snake_case maps field-for-field into `DiarizationResult`; and a
cancelled task refuses to produce one.

**Two decisions are the ones worth keeping.** The idempotency key is fresh on every run —
the sidecar's whole design is that a key it has seen answers from the journal in
milliseconds, which would make this test fast and worthless, still passing long after the
model stopped working. And the busy submission happens in `beforeAll` rather than in a test
body, because from a test body it races the forty-second run — and losing that race does not
fail loudly, it quietly starts a second real diarization.

The audio is committed, eleven seconds of four alternating macOS-TTS turns, with
`packages/engine/scripts/make-2spk-fixture.mjs` beside it: a binary in a repo with no way to
regenerate it is a fact nobody can check. The method is S7's, so the cumulative offsets *are*
the reference and nothing is hand-labelled. What the test asserts about content is the
**A-B-A-B pattern** at each reference turn's midpoint, never which label pyannote chose —
`SPEAKER_00` is meaningless across runs, which is the reason `identity.ts` exists, and a
pattern also survives pyannote splitting a turn in two. First run: 2 speakers, 4 turns, every
boundary within about 50 ms.

Phase 3's Definition of done also had two items still recorded as blocked that this morning's
sitting had already closed — the rename demo and the end-to-end run on real audio. Corrected,
with what was actually run. `scribe.ts` and the realtime-factor estimate are the two that
genuinely remain.

## Phase 4b, in one sitting

### The image never contained the thing its own header promised

The Dockerfile opens with "one image for both halves of the sidecar: pyannote diarization
(Phase 3) and faster-whisper ASR (Phase 4b)". The `pip install` three lines below it lists
pyannote and not faster-whisper. Nothing had failed, because nothing had asked.

Found by reading the install line rather than the comment above it, which is the only way
this class of error is ever found — and Phase 4's own prerequisites table says Phase 3
delivers "the sidecar image". It delivered half of one. Amendment 49. The fix is one line and
~100 MB, because faster-whisper is CTranslate2 rather than a second torch stack, which is
what keeps one image the right answer now that the second half is real.

### The registry served two workloads and would have averaged them

`TaskRegistry` kept a single rolling window of the last five realtime factors, and
`/health.realtime_factor_estimate` is what the engine shows a user **before a diarization**.
Phase 4b gives that registry a second kind of task. Measured on this box the same afternoon:
pyannote at 0.27–0.51x, `tiny` at 2.02x.

A shared window would have made the diarization estimate drift according to how much ASR ran
that day, and the symptom would have been a number nobody could explain rather than an
exception. Keyed by workload now — `diarize`, `asr:<model>` — and per *model*, because
`large-v3` and `large-v3-turbo` differ by 2–3x. Amendment 50. `/health` gained
`realtime_factors` beside the unchanged headline field, and `thibi models list` prints it.

### Two decisions that are not in the plan

**The ASR model loads lazily and one at a time.** pyannote's model is configuration and loads
at startup; the ASR model is a *request parameter*, and eagerly loading three of them would
cost several GB on an instance that may only ever diarize.

**`model` is allowlisted.** It reaches `WhisperModel(name)`, which downloads and runs whatever
it is handed, and the sidecar is unauthenticated *by design* — it holds no credentials
precisely so it can be trusted with none. Six lines of config close "any request can make it
fetch arbitrary weights".

### The column that is not a probe

Every other column of the matrix comes from `thibi probe languages` and real HTTP responses.
faster-whisper runs locally, and for a local model "will it accept this code" has a better
answer than a status code: the Whisper tokenizer either has a token for the language or it
does not. 100 codes, extracted from the built image and committed with their provenance.
95 of 116 registry languages get a row; the 21 without one are the long tail, which is the
product's thesis restated from the model's side.

The user chose how to encode the doubt: `probe-only` where Whisper has been measured fine,
`suspected` for the codes where the identical `whisper-large-v3` weights were measured
mangling output. Never `measured-failure`, because nobody has run *this* transport.

### And Burmese left a list the product is built on

`exclusiveTo: 'google'` was 21 and is 20. `my` has a Whisper token, `suspected` leaves
`supported: true` by the overrides file's own doctrine, so a third provider claims Burmese —
on no evidence at all. The matrix test caught it, which is exactly what it is for.

The honest reformulation is a single word: **"only Google is *known* to work for Burmese"**,
not "only Google works". Amendment 51, and `types.ts` carries the correction beside the
number it invalidates. faster-whisper serves the weights Groq was measured returning
Myanmar-script non-words from, so measuring it on Burmese is now the single highest-value
measurement Phase 5 can make, and the expected outcome is that this number returns to 21.

# Second sitting — the Phase 5 metrics layer

Executed against [`plans/phase-05-eval-harness.md`](../plans/phase-05-eval-harness.md), on
branch `phase-5/metrics`. **Scope was the metrics layer only** — the eleven files from
`levenshtein.ts` to `parity.json`. `packages/eval`, the `thibi eval` command, the FLEURS
loaders, the cache, the budget, the reports, `tiers.ts` and the CI workflow are deliberately
not started; they need live provider keys and network downloads, and stopping at the metrics
boundary was the point rather than a shortfall.

The layer exists because of a finding from the parallel sitting: a provider reported genuine
per-word confidence of **0.892** on completely fabricated output, Vietnamese boilerplate
returned for Burmese audio. Confidence measures a decoder's certainty about its own next
token, not whether the audio contains any of it. Script integrity catches the wrong
*alphabet* and scores Myanmar-script non-words 1.00. CER against a reference is the only
thing in this repo that can make the stronger claim, which is why these are the most
correctness-critical pure functions in the tree and why they are asserted against `jiwer` and
`sacrebleu` rather than against their author's confidence.

## The parity fixture, done first

`pip install` of the pinned libraries was the one thing that could have made the whole plan
unbuildable here, so it went first rather than last. It worked: **jiwer 4.0.0, sacrebleu
2.6.0, CPython 3.11.8**. `packages/core/scripts/gen-parity.py` ran for real and
`__fixtures__/parity.json` holds 19 sentence cases plus a corpus block of numbers those
libraries produced. Nothing in it is hand-written — a fixture whose expectations we invented
would only assert that our code agrees with itself.

Reading `sacrebleu/metrics/chrf.py` instead of porting from the plan's snippet was worth the
ten minutes twice over. `_get_match_statistics` is `hyp_count if ref_ngrams else 0`: at any
order where the reference has no n-grams at all, the hypothesis count is reported as **zero**
and the order drops out of the average. The plan's `overlap()` always reports it, which
scores a short hypothesis against a long reference differently from sacrebleu.
`chrf-asymmetric-short` is the case that catches it. The metric also slices Python `str`,
i.e. code points, so `astral-emoji` fails any port reaching for `.length` or `charAt`.

Three cases are in the fixture **because** they disagree with jiwer, tagged with a
`divergence` string so the test asserts the disagreement rather than tripping over it:

- `empty-ref` — jiwer's `process_words` special-cases an empty reference and returns the raw
  insertion count, so `jiwer.wer("", "a b c")` is `3.0`. That is not an error rate. We return
  `null`.
- `padded-whitespace` — jiwer applies `Strip()` first; we measure the string we were handed
  and leave stripping to `normalizeForScoring`, so there is one normalizer in one place.
- `tab-separated` — jiwer's tokenizer collapses runs of **two or more** whitespace characters
  to a single space and then splits on `' '` alone, so a lone tab is never a boundary. `the`
  + tab + `cat sat` is two tokens to jiwer and three to us, and jiwer therefore reports WER
  **1.0** for a sentence with one wrong word where we report 1/3. That is the small concrete
  form of §5.5's argument, and reconstructing jiwer's number needs jiwer's tokenizer, which
  is what the test does.

Two additions to what §5.7 specifies, both worth more than they cost. The fixture stores
**counts as well as rates**, because a rate can match for the wrong reason — compensating
errors above and below the line. And it has a **corpus block**: `corpusCer`, `corpusWer` and
`corpusChrf2` are ratio-of-sums and aggregate-then-score, and a drift to the mean of the
sentence values would pass every sentence-level assertion, look completely harmless, and move
every language in the tier table.

## What the plan got wrong

Six amendments, 54 to 59. 52 and 53 are reserved for the parallel sitting's write-up.

**`script-integrity.ts` was already built, under another name.** Phase 5's deliverables table
names a file that Phase 4a had shipped as `metrics/script.ts`, and §5.9 sketches a fresh
implementation beside it. The sketch is the weaker of the two on four counts — bare `number`
return, empty transcript scored `0` as though that were a measurement, one block list instead
of a script **plus its `altScripts`** (without which a correct Cyrillic Serbian transcript
scores 0, and `sr-RS` is 7% Cyrillic across the FLEURS dev set), and no stray characters, so
a failure prints `0.02` instead of `0.02 (stray: A S E N Y K)`. Two implementations of the
metric that decides `tier: unsupported` is precisely the drift the harness cannot afford, so
this is a **rename** and the reasoning is written into the file's header. Amendment 54.

**`ScoreProfile` is not the shape §5.6 specifies, in three places, and a fourth has no data
behind it at all.** `nativeDigitBase?: number` cannot express Arabic script, which has two
native digit sets — Arabic-Indic U+0660 and Extended Arabic-Indic U+06F0 — either of which a
provider may return against the same reference; one base folds one set and leaves the other
wrong at every digit. `zeroWidth` as a single enum cannot both strip Burmese's ZWJ and keep
Sinhala's, where it is semantic. And rule 5 had to become **unconditional**, ignoring
`digits.foldToLatin`, because that flag is `false` for every script in the tree — it is a
rendering policy about what a user should see, and honouring it here would have meant rule 5
never fired at all.

The fourth is the one to carry forward: **`letterlikePunct` has no registry field to come
from.** `text.punctuation` holds `sentenceEnders` and `quotes` and nothing else, so Somali's
glottal apostrophe and Hausa's compounding hyphen are stripped as punctuation, two words
merge into one, and both languages' WER is overstated at every occurrence. The mechanism is
built and tested against a hand-made profile; the data does not exist. Amendment 55.

**Zawgyi conversion is injected rather than imported.** §5.6 has `normalize.ts` importing
`is-zawgyi` and `rabbit-node`, and the Definition of done permits them as core's only runtime
dependencies. Neither is in the tree, core has zero runtime dependencies today, and it is
loaded into a React client bundle — so `ScoreOptions.convertZawgyi` is the seam and
`@thibi/languages`, which already owns `text.zawgyiApplies` and the `'zawgyi'` normalizer id,
is where the real detector and converter belong. `normalizeForScoring` **throws** when a
profile has `zawgyiApplies: true` and no converter arrives. Loud, not lenient: silently
skipping conversion reports a *correct* Burmese transcript at ~100% error, which reads as a
provider failure, and nothing else in the suite would catch it. Amendment 56.

**`bootstrapCi` returning `[NaN, NaN]` was a live trap.** NaN compares `false` against every
comparison, so a language with no clips would have sailed straight through `ciHi <= 0.20` and
landed in the tier table with an interval printed as `NaN`. It returns `null`, like every
other "undefined" in this layer. Amendment 59, along with two vocabulary corrections:
`'spaces'` not `'space'` — the registry's spelling, and a profile is meant to be a projection
of the registry with no translation step to get wrong — and `wer()` taking the existing
`SegmentationRules` shape so word segmentation for timings and for scoring cannot become two
different opinions.

## The correction that came from a red test

**A grapheme cluster is not a Burmese syllable.** I wrote
`expect(units('ကြန်', 'grapheme')).toHaveLength(1)` and it failed with `['ကြ', 'န်']`. Measured
properly on Node 22.18 / ICU 77.1:

```
ကြန်         4 code points, 2 clusters   ['ကြ', 'န်']
မြန်မာ        6 code points, 4 clusters   ['မြ', 'န်', 'မ', 'ာ']
နေပြည်တော်    10 code points, 5 clusters   ['နေ', 'ပြ', 'ည်', 'တေ', 'ာ်']
```

`မြန်မာ` is two syllables and four clusters, and `တော်` splits with its vowel sign in a
different cluster from its consonant. UAX #29's default rules break before a consonant
whatever medial or asat binds it to the previous one. Rule 7 is unaffected — both columns are
reported and the tier is assigned on code points — but the *wording* is: grapheme CER is
well-defined and reproducible and earns its place on Yoruba diacritics, and it is not "what a
human would count by hand" for Mymr. That is exactly how a column heading comes to be read as
a syllable error rate.

Two comments in the tree said otherwise. `script.test.ts` called those four code points "one
grapheme cluster"; its assertion was always about code points, so only the claim beside it
changed. `timing/interpolate.ts` is Phase 1's and its **count** is right — `မင်္ဂလာပါခင်ဗျာ` is
15 code points and 11 clusters — but its reason, that a grapheme keeps a vowel sign with its
consonant so a timing cannot land on half a stack, is not: `လ` and `ာ` are separate clusters.
Left alone beyond amendment 57, because it is another phase's file and its behaviour is not
wrong, only its justification.

Every defect above came from running something. None came from re-reading it.
