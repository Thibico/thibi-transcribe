from a provider accepting a code.

Written as per-phase documents rather than one file deliberately — a phase plan is what
someone opens when starting that phase, and it outlives the session that produced it.

## Spikes

### `bed2be8` 21:21 — Record Phase 0 spike results; amend the long-audio routing rule

Three decision gates run against Google STT v2 (`chirp_2`, `my-MM`, `asia-southeast1`)
using a 106-second Burmese news clip, plus 30-minute and 2-hour inputs synthesised by
concatenation. Full method and numbers in
[`plans/phase-00-spike-results.md`](../plans/phase-00-spike-results.md); the questions are
posed in [`plans/phase-00-spikes-and-registries.md`](../plans/phase-00-spikes-and-registries.md).

**S2 PASS** — word confidence is genuine: 101/101 words, 101 distinct values, full
start and end offsets. Low-confidence QA highlighting is viable on the primary provider.

**S1 FAIL** — speech adaptation does not work on Chirp. Boost 0/10/20 produced
byte-identical output; relevant keyterms produced zero lexical change and did not fix a
targeted error; an *irrelevant* phrase set corrupted a word the baseline got right, in all
five occurrences. Consequence: the engine must never send `config.adaptation` to Chirp, and
the glossary entity pass in [Phase 6](../plans/phase-06-llm-passes.md) becomes the *only*
entity mechanism for the exclusive-language set rather than a supplement to keyterm biasing.

**S3 works, but inverts the routing rule.** `batchRecognize` runs at a flat 5.9× realtime
(305 s for 30 min, 1211 s for 2 h) while chunked parallel sync at concurrency 8 is 3.6–7×
faster at every size, with zero 429s across 136 requests. The 15-minute duration threshold
was deleted from the overview: chunked sync is the default at any length and batch became
an admin cost choice. This rewrote the premise of
[Phase 2](../plans/phase-02-batch-recognize.md).

Three further measurements that changed implementation plans: a batch operation can report
`done: true` with no operation-level error while `results[uri].error` is set (1 run in 5);
hard cuts lose 2–3 words per seam, which is the measured justification for the
[Phase 1](../plans/phase-01-engine-core.md) overlap-and-LCS merge; and sequential chunk
cutting is 200 s of the 338 s two-hour prep, so it must be parallelised.

Still open: the Dynamic Batch **rate** advantage is unverified — `totalBilledDuration`
reports audio duration, not price. Since cost is now batch's only justification, it should
be confirmed against an actual bill before [Phase 2](../plans/phase-02-batch-recognize.md)
is scheduled.

### `9378190` 21:36 — Bootstrap the monorepo

pnpm workspaces + Turborepo over nine packages; ESM everywhere with `tsc -b` project
references and no bundler, because `packages/core` must be importable from a React client
component. 45 files.

Two ESLint rules landed as **architecture, not style**, both asserted by
[`tests/lint-rules.test.ts`](../tests/lint-rules.test.ts) rather than trusted: the engine
packages cannot read `process.env`, `process.cwd()` or `__dirname` (everything arrives via
`EngineContext`), and the dependency direction is one-way `core ← languages ← db ← engine ←
apps`. They are free to add now and a refactor to add later, which is why the plan put them
in Phase 0.

`packages/core` shipped one real module rather than a placeholder: a quote-aware TSV
parser. FLEURS files are tab-delimited but CSV-quoted, so `split('\t')` leaves stray quote
characters on the reference and every CER computed against it is quietly wrong —
[overview amendment 4](../plans/00-overview.md). Needed here by the script inferencer and
again by the [Phase 5](../plans/phase-05-eval-harness.md) harness.

The old app's Google-region doctrine was deleted rather than ported, and CI now fails on
the region string appearing in source outside the single file allowed to hold its default.
It was measured false twice.

### `b799971` 21:55 — Add the language registry

116 language codes over 26 scripts, seeded from the 102 FLEURS configs plus 5 non-FLEURS
Google locales plus 9 extra locales, and compiled to a deeply frozen
`registry.gen.ts`. Implements §0.3 of the phase plan.

Scripts are **inferred from each language's own FLEURS reference text**, not parsed out of
the region subtag, because the subtag lies: `sd-IN` is Sindhi in Arabic script and
`pa-Guru-IN` carries its script in the middle of the tag. Both are now regression tests.

Two measurements changed the design mid-seeding:

- **Digraphia has to be measured by whole sentences, not character share.** Latin runs at
  2–5% of a Telugu, Lao, Nepali, Korean or Chinese corpus from acronyms alone, so a
  character threshold produced five false positives. Counting sentences whose majority
  script differs leaves exactly one real case — Serbian, 11 of 199 FLEURS rows wholly
  Cyrillic. `altScripts` records it so the [Phase 5](../plans/phase-05-eval-harness.md)
  script-integrity check cannot fail a correct Cyrillic Serbian transcript. That check
  exists to catch Groq romanising Burmese; it must not fire on a language simply being
  written the way it is written.
- **Native digit sets must be a list, not a string** — Arabic script needs both
  Arabic-Indic and Extended Arabic-Indic, and a single string leaves one unfolded.

The generator's own integrity check caught a bug in one of its own rules: "RTL script
implies `waveHint: rtl`" is false in that direction, since Persian, Hebrew and Urdu are RTL
and covered by OpenAI.

`my-MM` is the only seeded `verified` language and its notes say why — operational use, not
measurement. The harness can award beta and experimental on its own; it can never award
verified.

### `cbb474c` 22:18 — Add the thibi CLI and the live provider matrix

`thibi lang list|show` and `thibi probe languages`, plus the committed result of probing
all 116 codes against Google `chirp_2`, OpenAI `whisper-1` and `gpt-4o-transcribe`, and
Groq `whisper-large-v3`. Implements §0.4.

**The headline reproduces exactly: 44 languages Google handles that no OpenAI model will
accept**, measured live, against 44 measured by hand on 2026-07-30 — the figure the whole
product's strategic case rests on.

Four things the live run taught that no amount of planning would have:

1. **Every provider words a language rejection differently and none uses a distinguishing
   status code** — Google `Bad language code`, OpenAI `Language code 'ha' is not
   recognized`, Groq `unsupported language: xx`. A three-code smoke test caught this
   *before* the paid sweep; the original pattern would have recorded all 116 OpenAI results
   as `error` and the 44 would have come out zero. The recorded messages are now the test
   fixtures. [Phase 4](../plans/phase-04-whisper-providers.md) inherits this table.
2. **Groq's on-demand tier allows 20 requests per minute.** The first sweep turned 55 of
   116 languages into `unknown` — the classifier correctly refusing to read a 429 as a
   rejection, which left holes rather than wrong data. Honouring `Retry-After` and
   self-throttling to ~18 rpm turned those into 96 accepted and 20 rejected.
3. **Chirp returned a transcript and word offsets for all 116 codes.**
   [Overview Risk 2](../plans/00-overview.md) expected long-tail languages to come back
   with an empty word array; on this clip none did. The no-words path is still built first
   in [Phase 1](../plans/phase-01-engine-core.md) — one clip on one day is evidence, not
   proof, and it also covers `gpt-4o-transcribe`, which returns no timestamps at all.
4. **The probe fills `wordTimestamps` for real**, extending spike S2's single-language
   result across the whole matrix for free.

Classification is a pure function with 28 tests, because the one way to ruin this file is
to record a rate limit as a rejection — a language would silently vanish from the picker. A
429 preserves the previous row and does not refresh `probedAt`; a 401 aborts before
anything is written.

## Corrections back into the plans

### `774009d` 22:22 — Amend the plans with what Phase 0 measured

The design record should not still assert numbers the implementation disproved.

**The "44" and "exclusive to Google" are two different figures and the phase plan conflated
them.** `--provider google --not-supported-by openai` is 44. `--exclusive-to google`,
meaning no other provider at all, is **21** — the research's 20 plus Burmese. Burmese is
there only because `matrix-overrides.json` overrides a 200: Groq *accepts* `my` and returns
non-words. The overrides mechanism proving itself on the one language this project was
built for is the best available demonstration that accepting a language code proves
nothing. `--not-supported-by` was added because without it the headline figure was not
expressible on the CLI.

Also folded in: Risk 2 downgraded but not deleted, and three findings that constrain later
phases — the rejection-message table and the Groq rate limit for
[Phase 4](../plans/phase-04-whisper-providers.md), and sentence-level digraphia for
[Phase 5](../plans/phase-05-eval-harness.md). Recorded as amendments 16–20 in the
[overview](../plans/00-overview.md).

### `8c22c11` 22:24 — Close the last Phase 0 gap: S2 word confidence per language

The phase plan requires S2's verdict *per language*, not as one global answer, and only
Burmese had ever been measured. Ten languages chosen for where the word array was most
likely to be missing — `my-MM, ha-NG, yo-NG, am-ET, km-KH, ps-AF, ceb-PH, om-ET, zu-ZA,
si-LK`. Every one returned words, every word carried a confidence and both offsets, and
distinct values equalled word count throughout. No placeholders anywhere.

The more useful finding: **the confidence signal is calibrated.** The clip is Burmese. Read
as Zulu it scores 0.128–0.333; read as Burmese, 0.738–0.973. Confidence tracks whether the
model is actually right rather than decorating the output — which is what makes
[Phase 12](../plans/phase-12-ui-editor.md)'s uncertain-word toolbar worth building and
gives its 0.6 default threshold an empirical basis instead of being a round number.
