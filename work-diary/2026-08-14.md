## The LLM evals were delegated to a cloud agent, and it stalled

Executed against [`plans/phase-05-eval-harness.md`](../plans/phase-05-eval-harness.md) §5.10.

Phase 5's ASR half was finished and merged on 2026-08-13; the LLM half — `cleanup`,
`translate`, the `--gate` and `report/llm.ts` — was the natural next piece, and the user asked
whether a cloud worker could take it. Two things were established before dispatching, and both
still hold:

**`packages/engine/src/llm/` does not exist.** §5.10 requires `packages/eval` to import the
*real* `buildCleanupPrompt` from the engine and never hold a prompt string of its own, so stub
builders have to land in Phase 5 with Phase 6 replacing only the prompt text. That is a
prerequisite, not part of the eval work.

**A delegated agent cannot produce the numbers.** There are no API keys in a cloud
environment, deliberately, so it can build the machinery and unit-test it against injected
fakes but the report stays empty until someone runs it locally. The gate's acceptance
criterion — reproducing the research finding that `current` is worse than `control` in every
language — is only checkable after that run.

The agent was dispatched with a brief covering both, plus the four rules in §5.10 that look
like implementation details and are not: the injected LLM call (amendment 75), `promptId` and
`promptVersion` in `paramsHash` (without which the gate is theatre), `content_delta` as a
contract check rather than a quality score, and a prohibition on writing the research doc's
published numbers into a report or test as though they had been observed here.

**It stalled after the reading phase**, with the watchdog reporting no progress for 600
seconds. Nothing was written: no branch, no commits, nothing to salvage.

That is one data point and not a verdict on delegation. But the brief was long and
front-loaded with five documents to read before any edit, which is a plausible way to spend a
watchdog window without producing anything — and it is the specific thing to change if it is
tried again. The brief itself was not wasted: it is now the task description in
[`plans/note-for-next-session.md`](../plans/note-for-next-session.md), to be worked locally.
